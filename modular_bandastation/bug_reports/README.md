# Багрепорты из игры

Порт [Paradise #30376](https://github.com/ParadiseSS13/Paradise/pull/30376),
изначально из CM-SS13. Форма на русском использует штатные компоненты TGUI.

`report-issue` во вкладке OOC, кнопка в лобби и ESC → Report Bug открывают форму.
Игрок заполняет заголовок, ожидаемое и фактическое поведение, последствия,
шаги воспроизведения и необязательные логи. Кнопка «Опубликовать на GitHub»
сразу создаёт issue без проверки администрацией. Между отправками — пять минут
на ckey. Во время отправки повторное нажатие заблокировано; закрытие окна
не прерывает уже начатый запрос.

В приватной серверной конфигурации (`config/dev_overrides.txt` для локалки):

```text
GITHUBURL https://github.com/SpaceStation220/Primera
GITHUB_API_TOKEN <токен выбранного репозитория>
```

Для fine-grained токена достаточно доступа к выбранному репозиторию и
`Issues: Read and write`. Токен скрыт и заблокирован для административных
изменений через VV/proc call, не передаётся в TGUI и не хранится в репозитории.
Для публикации необходимы оба параметра; токен не требуется самому игроку.
Без токена форма открывается, но попытка отправки сообщает об ошибке
и сохраняет заполненные поля.

При ошибке API заполненный черновик сохраняется до закрытия формы.
Если окно закрыто во время отправки, после ошибки черновик можно снова открыть,
в том числе до истечения cooldown; повторная отправка доступна через пять минут
после предыдущей попытки.
После сетевого сбоя перед повторной отправкой проверьте Issues: запрос мог
дойти до GitHub без ответа серверу. Черновики и cooldown живут в памяти сервера
и не сохраняются после перезапуска.

Для ручной проверки на тестовом репозитории: отправить заполненную форму
обычным игроком, убедиться, что issue создаётся сразу, а повторная отправка
ограничена cooldown. Проверить поля, раунд, версии BYOND, коммиты и test merges
в issue. Повторить с неверным токеном и убедиться, что форма сохраняет текст
для повторной отправки. Закрыть окно во время запроса и проверить уведомление
автора после ответа GitHub.

Unit tests `bug_report_validation`, `bug_report_repository`,
`bug_report_cooldown`, `bug_report_lifecycle`, `bug_report_submission` не отправляют
HTTP-запросов.
Тесты TGUI проверяют обязательные поля, прямую публикацию и блокировку
повторной отправки.
