# Проверка предыстории

`run_tests.ps1` запускает серверные регрессии интеграции Background. Описание функций — в [README модуля](../../modular_bandastation/sierra_background/README.md), основания зависимостей — в [DEPENDENCIES.md](../../modular_bandastation/sierra_background/docs/DEPENDENCIES.md), источники — в [DONOR.md](../../modular_bandastation/sierra_background/DONOR.md).

Из корня BandaStation в PowerShell 7, с установленными BYOND и native-библиотеками проекта:

```powershell
pwsh -File ./tools/sierra_background/run_tests.ps1
```

Если BYOND установлен в другой каталог:

```powershell
pwsh -File ./tools/sierra_background/run_tests.ps1 -ByondBin 'C:\BYOND\bin'
```

Для проверки очистки объектов добавьте `-IncludeGarbageCollection`; `-ConfigDirectory` позволяет использовать отдельную минимальную конфигурацию без локального списка разрешённых видов:

```powershell
pwsh -File ./tools/sierra_background/run_tests.ps1 -ConfigDirectory 'data/background-ci-config' -IncludeGarbageCollection
```

Каталог конфигурации должен существовать заранее. Не запускайте одновременно тестовый и игровой миры из одной рабочей копии: штатный `server_maint` очищает общий `tmp/` при запуске и завершении каждого мира. Отдельные рабочие копии имеют разные временные каталоги.

Скрипт автоматически находит группы `sierra_background_*` в `tests/*.dm` модуля, создаёт игнорируемую Git тестовую обёртку, компилирует и запускает отдельный тестовый мир. Дополнительно выполняются штатные проверки preferences и языков. Используются изолированные тестовые сохранения; реальные файлы персонажей не используются. Число групп определяется текущими исходниками.

Прогон успешен при завершении компиляции и сервера без ошибок, отсутствии runtime errors, наличии `clean_run.lk` и успешном результате каждой ожидаемой группы в `data/unit_tests.json`. Скрипт выводит путь к журналам конкретного запуска. Результаты конкретных прогонов и ограничения проверок фиксируются в [VALIDATION.md](../../modular_bandastation/sierra_background/VALIDATION.md).

Регрессии проверяют фракционную иерархию, серверный отбор вариантов, пригодность миров и авторские уточнения, условные социальные поля, сохранение старых ID и заметок, точные миграции, независимую веру, языки и генерацию имён. Приватный блок антагониста требует отдельных проверок доступа владельца, снимка фактического персонажа, переключения слотов и соответствия назначенному работодателю. Эти данные не должны попадать в DNA или публичные структуры; тесты не должны менять назначение ролей и снаряжение.

Серверный прогон дополняется TGUI-тестами и ручной проверкой меню в настоящем BYOND-клиенте. В интерфейсе следует проверить вложенное подразделение, блоки четырёх социальных видов, историческое предупреждение, независимую веру и раскрытие описания по всей площади кнопки при разных размерах окна. Успех серверных тестов сам по себе не подтверждает визуальную проверку клиента.
